# What If? Analysis

A [[Wiki/concepts/structured-analytic-techniques|SAT]] that assumes an unexpected event has already occurred and asks analysts to explain how it could have happened. Forces consideration of low-probability scenarios and identifies early warning indicators.

---

## Purpose

Overcome the tendency to dismiss unlikely scenarios. By *assuming* the scenario has occurred, the technique bypasses the psychological resistance to examining unwelcome possibilities.

---

## Method

1. State: "Assume that [unlikely event] has occurred"
2. Work backward: how could this have happened?
3. Identify the chain of developments that would lead to this outcome
4. Derive indicators/signposts (see [[Wiki/concepts/indicators-or-signposts-of-change|Indicators or signposts of change]]) that would signal the scenario is emerging

---

## Biases Primarily Controlled

| Bias | How this technique counters it |
|------|-------------------------------|
| [[Wiki/concepts/hindsight-bias\|Hindsight Bias]] | The primary technique for this bias — by *assuming* an unexpected event has already occurred, it mimics hindsight prospectively, using it productively |
| [[Wiki/concepts/status-quo-bias\|Status Quo Bias]] | Forcibly displaces the status quo; the current state is no longer the reference point |
| [[Wiki/concepts/overconfidence-bias\|Overconfidence Bias]] | Pre-mortem thinking consistently reduces overconfidence by requiring engagement with failure paths |
| [[Wiki/concepts/confirmation-bias\|Confirmation Bias]] | By starting from the assumed contrary outcome, it forces evidence to be marshaled in the disconfirming direction |

---

## Applied in Cybersecurity

- **Incident Responders**: explores how incidents might unfold unexpectedly; prepares responders for worst-case scenarios ([[Wiki/sources/riley-sats-cybersecurity-2024|Riley: SATs in Cybersecurity (2024)]])
- **Cybersecurity Auditors**: explores how unforeseen events (sudden policy changes, new regulations) could impact security posture
